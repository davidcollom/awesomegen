# awesomegen backlog

Prioritised, actionable work items. Every item names the files it touches so
that it can be picked up without further investigation.

**P0** - do before the next release; they affect correctness, security or the
ability to ship.
**P1** - do soon; they remove friction or close a real gap.
**P2** - nice to have; they improve the project but nothing is blocked.

Status: `open` unless stated otherwise.

---

## P0 - correctness and shipping

### 1. The README claims the wrong Go version and points at the wrong badge
`README.md:4` uses the `release.yml` workflow for the build badge, and
`README.md:7` says "a Go 1.23 CLI" while `go.mod` requires `go 1.27.3`.
Users on Go 1.23 cannot build the project at all.
* Point the badge at the new `ci.yml` workflow.
* Say Go 1.27, or derive the version from `go.mod`.
* Fix the typo at `README.md:64` (`aesomegen` -> `awesomegen`).
* Replace the manual `golangci-lint run` snippet with `make lint`.

### 2. No end-to-end test of the CLI
The unit tests cover the config loader, the filters, the renderer and the
scraper in isolation, but nothing runs the whole pipeline: scrape a Star
List, enrich it, render the Markdown and write the file. `testdata/stars_list_page.html`
exists and could be served from a `httptest` server.
* Add a test in `cmd/awesomegen` that points the CLI at a fixture config and
  a fixture Star List page, and asserts the generated `README.md`.
* Assert the "refusing to overwrite with an empty README" behaviour end to
  end, not only in the renderer.

### 3. `internal/github` is only 35.7 % covered
`internal/github/client.go` is where authentication, rate limiting,
pagination and error handling live - exactly the code that breaks silently.
* Cover the unauthenticated and the authenticated path.
* Cover the rate limit response (403 with `X-RateLimit-Remaining: 0`).
* Cover a repository that was deleted between the scrape and the lookup
  (the `render.LookupError` path in `cmd/awesomegen/main.go:94`).

### 4. No coverage floor in CI
The `ci.yml` workflow uploads `coverage.out` but nothing fails when
coverage drops. The total is currently 75.0 %.
* Fail the build when the total coverage falls below a floor (70 % to start
  with) and raise the floor over time.
* Add the coverage summary to the job output so a regression is visible
  without downloading the artefact.

### 5. The Star List scraper depends on GitHub's HTML
`internal/scrape/scraper.go` parses the HTML of
`https://github.com/stars/<user>/lists/<slug>`. GitHub changes that markup
without notice and the tool then silently produces an empty list.
* Record a second fixture from a different page shape and test both.
* Add a scheduled (cron) CI job that runs the scraper against a public list
  and fails when the page structure no longer matches the fixture.

## P1 - gaps that should be closed soon

### 6. `example/jsonschema.json` is a stale duplicate of the real schema
It uses a different `$schema` draft, a different `$id` and has none of the
descriptions that `config-schema.json` has. Only the generated file is
maintained by `make schema`.
* Delete `example/jsonschema.json`, or replace it with a copy that is
  regenerated by `make schema`.
* Point the README at `config-schema.json`.

### 7. `internal/action` is an empty stub
`internal/action/entrypoint.go` contains nothing but a comment.
* Either implement the Action specific input parsing there, or delete the
  package. Right now it is dead weight in the module.

### 8. The CLI has exactly one flag
`cmd/awesomegen/main.go:126` registers `--config`/`-c` and nothing else.
* Add `awesomegen validate <config>` - parses and validates a config file
  without touching the network. It is the single most useful missing
  command and it is trivial to implement on top of `config.Load`.
* Add `awesomegen schema` that prints the JSON schema, so users do not have
  to download it from the repository.
* Consider `--dry-run`, which renders to stdout instead of writing a file.

### 9. `cmd/awesomegen/main.go:128` calls `os.Exit` while a deferred call is pending
`gocritic`'s `exitAfterDefer` reports it; the check is currently disabled in
`.golangci.yml`.
* Move the signal handling into a helper function, or return the error from
  `main` through a `run() error` function, so the deferred `stop()` runs.

### 10. Dead code in `internal/render/helpers.go`
`func slug` at `internal/render/helpers.go:39` is not used anywhere. The
`unused` linter reports it and the finding is excluded in `.golangci.yml`.
* Delete the function and remove the exclusion rule.

### 11. `.dockerignore` does not exclude the build output
`bin/` and `dist/` are copied into the Docker build context, which makes the
build slower and can leak a locally built binary into the context.
* Add `bin/`, `dist/` and `coverage.out` to `.dockerignore`.

### 12. Dependabot does not watch `Dockerfile.goreleaser`
`.github/dependabot.yaml` has a `docker` ecosystem entry for `/`, which
covers the root `Dockerfile` only. The digest pin in `Dockerfile.goreleaser`
would silently go stale.
* Add a second `docker` ecosystem entry for the new file, or move the
  image definition into a single file.

### 13. No `.gitattributes`
Without it, Windows checkouts can produce CRLF line endings, which makes
`gofmt -l` report every file.
* Add a `.gitattributes` with `*.go text eol=lf` (the golangci-lint
  documentation recommends exactly this).

### 14. `CODEOWNERS` is a catch-all
`.github/CODEOWNERS` contains a single `* @davidcollom` line, so every
change needs the same reviewer and nothing is routed by area.
* Split it into paths (`.github/workflows/`, `internal/render/`,
  `internal/config/`, `docs/`) so that the right reviewer is asked first.

### 15. The action resolves `latest` by default
`action.yml` defaults the `version` input to `latest`, which makes a
workflow non-deterministic over time.
* Document in the README that pinning `version: v1.2.3` is recommended for
  reproducible workflows.
* Consider defaulting to the newest release *at the time the workflow file
  was written* instead.

### 16. macOS binaries are not notarized
The `notarize` block in `.goreleaser.yaml` is present but commented out,
because it needs a paid Apple Developer account, a "Developer ID
Application" certificate and an App Store Connect API key.
* Decide whether to buy the membership and enable the block, or to state
  explicitly in the README that the macOS binaries are unsigned.

### 17. The published container image is not documented
The image is pushed to `ghcr.io/davidcollom/awesomegen` with the tags
`vX.Y.Z`, `vX`, `vX.Y` and `latest`, but the README only shows the CLI and
the Action.
* Document the `docker run` invocation, including that the image runs as a
  non-root user and therefore cannot write into a mounted directory - which
  is exactly why the GitHub Action is a composite action and not a Docker
  action.

## P2 - improvements

### 18. A scheduled CI run
`ci.yml` only runs on pushes and pull requests. A weekly run would catch
upstream breakage (a new Go release, a changed GitHub API) before a user
does.
* Add a `schedule:` trigger with a weekly cron.

### 19. A `CHANGELOG.md`
Release notes are generated by GoReleaser and live on the GitHub release
page only.
* Either generate `CHANGELOG.md` in the release workflow, or state in the
  README that the release notes are the changelog.

### 20. Homebrew, Scoop and Nix packaging
The release already publishes binaries for macOS and Windows.
* Add the `homebrew`, `scoop` and `nix` sections to `.goreleaser.yaml`; they
  are supported by GoReleaser v2 out of the box.

### 21. Use the GitHub API instead of scraping HTML
`internal/scrape` parses HTML because the Star List API is not public.
* Investigate whether the GraphQL API exposes star lists after all; that
  would remove the whole scraping code path and its fragility.

### 22. Cache the GitHub API responses
Every run looks up every repository again.
* Add an on-disk cache keyed by repository and by ETag, with a short TTL.

### 23. Streaming rendering for very large lists
`internal/render/readme.go` builds the whole document in memory.
* Render into a `bufio.Writer` so a list with tens of thousands of
  repositories does not need the whole document in memory at once.

### 24. Verify that the tag matches the changelog
The release workflow accepts any `v*.*.*` tag.
* Add a check that the tag matches the version in the release pull request,
  and that the previous tag exists (a first release needs an explicit
  opt-in).

### 25. A reusable workflow for consumers
* Publish the CI workflow as a reusable workflow so that a consumer can call
  it instead of copying the steps.
